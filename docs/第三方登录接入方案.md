# 第三方登录接入方案

> 目标：把「一键登录 / 扫码登录」做成**运行期可配置**的能力。标准 OAuth2 渠道（LinuxDo 以及后续同类）只加一行配置就能上线；微信小程序这类换票协议不同的渠道，由业务模块提供协议实现，底座不引业务 SDK。

## 1. 能力范围

| 场景 | 入口 | 说明 |
| --- | --- | --- |
| 管理后台（PC）第三方登录 | 登录页第三方按钮 | 只放行 `portal=admin` 的账号；家长/学生账号仍在小程序登录 |
| 管理后台渠道配置 | 「系统管理 → 第三方登录」 | 渠道的端点、密钥、状态与字段映射；停用渠道不出现在登录页 |
| 管理后台绑定/解绑第三方账号 | 顶栏「个人信息」→ 第三方账号 | 绑定完成回跳 `?identityBound=`，只提示一次 |
| 小程序微信一键登录 | 小程序登录页 | 单账号直接进；多账号返回候选列表，选一个再签发令牌 |
| 小程序员工账号绑定微信 | 「我的」→ 微信 → 绑定微信 | 员工先用管理后台账号密码登录小程序，再补绑微信 |
| 小程序多账号选择 | `/pages/account-select/index` | 同一微信可同时绑家长与员工账号 |

**不做**：第三方账号自动注册（LinuxDo 只允许绑定已有账号）；网页端给家长/学生签发令牌。

## 2. 数据模型

### `sys_auth_provider`（渠道配置）

一行一个渠道。`provider_code` 是登录页与回调路径使用的外部标识（如 `linuxdo`），`provider_type` 对应代码里的协议实现（`OAUTH2` 由底座内置，`WECHAT_MINIAPP` 由教务模块实现）。

关键列：

| 列 | 用途 |
| --- | --- |
| `status` | `active` / `disabled`；停用渠道不出现在登录页 |
| `client_id` / `client_secret` | 渠道密钥；`client_secret` 经 `SensitiveCipher` 加密存储（`enc:v1:` 前缀，明文也兼容） |
| `authorize_url` / `token_url` / `userinfo_url` / `scope` | 标准 OAuth2 端点 |
| `token_auth_method` | `post`（表单传 client_id/secret）或 `basic`（HTTP Basic） |
| `redirect_uri` | 必须与渠道后台登记的回调地址完全一致 |
| `extra_config` | JSON：用户字段映射与可选 `webBaseUrl` |

`extra_config` 示例：

```json
{
  "userIdField": "id",
  "nicknameField": "name",
  "avatarField": "avatar_template",
  "unionIdField": "unionid",
  "appType": "website",
  "webBaseUrl": "https://example.com"
}
```

- 用户唯一标识默认按 `sub → id → openid → username` 兜底；字段名不固定时用 `userIdField` 指定。
- `appType` 默认 `website`；小程序侧固定写 `miniapp`。
- `webBaseUrl` 只在「后端回调地址与前端页面不同源」时需要（如开发环境前端 5173、回调指向后端 9080）。缺省取 `redirect_uri` 的源。

### `sys_user_identity`（身份绑定）

| 列 | 用途 |
| --- | --- |
| `provider_code` + `app_type` + `open_id` | 外部身份定位 |
| `union_id` | 微信开放平台统一标识；openId 未命中时按 unionId 再兜一层 |
| `user_id` | 系统账号（`sys_user_account.id`），外键 |
| `nickname` / `avatar_url` | 外部资料快照；登录时不回传昵称则保留旧值 |
| `last_login_at` | 最近一次通过该身份登录 |

- 唯一键 `(provider_code, app_type, open_id, user_id, deleted)`：**同一个外部身份允许绑多个系统账号**，这是小程序「家长 + 员工」多账号选择的基础。
- 解绑走**物理删除**（`UserIdentityMapper#physicalDeleteByIdAndUserId`），不留墓碑，避免解绑后重新绑定撞唯一键。
- 账号注销时由底座 `UserIdentityServiceImpl` 监听 `UserAccountDeregisteredEvent` 物理删除该账号的全部身份行；必须在物理删账号之前完成，否则外键 1451。

## 3. 代码分层

```
core/auth/social/
  ThirdPartyAuthProvider       协议 SPI：buildAuthorizeUrl / exchange
  OAuth2ThirdPartyAuthProvider 标准授权码流程（RestClient，无 SDK）
  AuthProviderRegistry         配置行 ↔ 协议实现
core/auth/service/
  ThirdPartyLoginService       网页端编排：state、票据、回调、换令牌
  AccountCandidateService      候选账号展示（不暴露真实 userId）
  UserIdentityService          身份绑定唯一读写入口
core/auth/controller/
  ThirdPartyAuthController     /api/auth/providers、/api/auth/oauth2/**
  UserIdentityController       /api/auth/me/identities
```

- 底座不依赖任何教培业务包；小程序微信登录仍在 `module-education` 的 `WechatAuthServiceImpl`。
- 底座基线脚本：`cornerstone-core/.../cornerstone/migration/V122__create_auth_provider_and_user_identity.sql`。
- 教培存量路径：`app/.../db/migration/V120`（建表）、`V121`（迁 `jp_wechat_binding` 并删表）、`V122`（种子）。

## 4. 网页端流程

```
登录页 GET /api/auth/providers
  → 点渠道：浏览器 302 /api/auth/oauth2/{code}/authorize
  → 渠道授权页
  → GET /api/auth/oauth2/{code}/callback?code&state
      ├─ state 失效/渠道停用 → /login?oauthError=…
      ├─ 未绑定账号          → /login?oauthError=not_bound
      ├─ 只有非管理端账号    → /login?oauthError=portal_not_allowed
      ├─ 恰好 1 个管理端账号 → /oauth/callback#ticket=…（票据 2 分钟、一次性）
      └─ 多个管理端账号      → /oauth/select#ticket=…（票据 5 分钟）
  → 前端 POST /api/auth/oauth2/exchange  { ticket } → LoginResponse
     或 GET 选账号后 POST /api/auth/oauth2/select { ticket, accountKey }
```

安全约定：

- **令牌不进 URL**：URL 里只有一次性票据，且放在 fragment（`#ticket=`），浏览器不会把它发到服务端日志。
- state 5 分钟、登录票 2 分钟、选账号票 5 分钟、绑定票 5 分钟，全部 Redis 存储 + `getAndDelete` 一次性消费。
- `accountKey` 是本次票据内的序号，前端拿不到也传不进真实 userId；服务端按票据里的 userId 列表解析。
- 网页端 `select/exchange` 都会再次校验账号启用状态与 `portal=admin`。
- 登录成功写操作日志 `login_provider`（`password` / `wechat_miniapp` / 渠道编码）。

### 绑定流程

```
个人信息面板 → POST /api/auth/oauth2/{code}/bind-ticket（需登录）→ { ticket }
  → 浏览器跳 /api/auth/oauth2/{code}/authorize?bindTicket=…
  → 回调把身份绑到当前账号 → /login?identityBound={code}
  → 路由守卫带标记回工作台，布局层 toast 一次并从地址栏清掉
```

## 5. 小程序多账号

`POST /api/auth/wechat/login` 的响应扩展为：

```json
{
  "registered": true,
  "auth": null,
  "ticket": "…",
  "accounts": [
    { "key": "0", "displayName": "张小明", "portal": "parent", "institutionName": "示范机构" },
    { "key": "1", "displayName": "张老师", "portal": "admin", "institutionName": "示范机构" }
  ]
}
```

- 只绑 1 个账号：`auth` 直接带回令牌，`accounts` 为空。
- 未绑任何账号：`registered=false`，前端进入注册页。
- 绑多个账号：前端进入账号选择页，`POST /api/auth/wechat/select { ticket, accountKey }` 换令牌。小程序端**不**限制 `portal=admin`，家长/学生/员工都可选。
- 员工绑定微信：密码登录小程序 → 「我的」→ 绑定微信 → `POST /api/auth/wechat/bind { code }`。绑定是追加关系，不覆盖该微信原有的家长账号。
- 令牌失效后的静默重登：微信登录态仍会自动重登；但若命中多个账号，自动重登无法替用户选择，会退回登录页重新选，绝不静默换账号。

## 6. 接入 LinuxDo（首个渠道）

### 6.1 在界面上配置（推荐）

「系统管理 → 第三方登录」（`/system/auth-providers`，权限码 `system:auth-provider:manage`）：

1. 在 <https://connect.linux.do/dash/sso> 创建应用，登记回调地址：
   - 生产同源部署：`https://<域名>/api/auth/oauth2/linuxdo/callback`
   - 本地开发建议填前端源，走 Vite 代理：`http://127.0.0.1:5173/api/auth/oauth2/linuxdo/callback`
2. 编辑「LinuxDo」这一行，填 `Client ID` / `Client Secret` / `回调地址`，确认端点（授权 / 令牌 / 用户信息）无误。
3. 状态改为「启用」并保存，登录页立刻出现「LinuxDo 一键登录」。
4. 首次登录若提示「尚未绑定系统账号」，先用账号密码登录，在「个人信息 → 第三方账号」完成绑定。

密钥由服务端加密保存，编辑时只回显「已配置」，不会把密文发到浏览器；留空保存表示保持原值。

### 6.2 直接改库（无界面时的兜底）

更新 `sys_auth_provider` 中 `provider_code='linuxdo'` 这一行：

- `client_id` = 应用 Client ID
- `client_secret` = 应用 Client Secret（明文可直接用，`SensitiveCipher` 对非密文原样返回；界面写入的是 `enc:v1:` 密文）
- `redirect_uri` = 上一步登记的地址
- `status` = `active`

用户字段映射已预置：`{"userIdField":"id","nicknameField":"name","avatarField":"avatar_template"}`。**不要**持久化 LinuxDo 返回的 `api_key`。

种子行初始为 `disabled`，避免未配置密钥时登录页出现死按钮。

## 7. 以后接新渠道

### 标准 OAuth2 / OIDC

在「系统管理 → 第三方登录」新增一行（或直接插 `sys_auth_provider`）：填端点、scope、`client_id/secret`、`redirect_uri`，`provider_type='OAUTH2'`，按需补 `extra_config` 字段映射。前端自动出现按钮，无需改代码、无需发版。

### 协议不同（微信网站扫码、公众号等）

1. 在业务模块实现 `ThirdPartyAuthProvider`（`type()` 返回新的 `provider_type`），用业务 SDK 换票并返回 `ExternalIdentity`。
2. 建一行 `sys_auth_provider`，`provider_type` 与实现一致。
3. SDK 依赖留在业务模块 `pom.xml`，不要下沉到 core。

## 8. 部署前置条件

微信开放平台/公众号与多数 OAuth 渠道要求**已备案域名 + HTTPS** 的回调地址；当前 Nginx 只有 80 端口与 `server_name _`。上线前需要：

- 域名解析与 ICP 备案；
- HTTPS 证书与 443 监听；
- Nginx 透传 `Host` / `X-Forwarded-Proto`（现有配置已带），后端回调后按 `redirect_uri` 的源跳回前端；
- 在渠道后台登记最终回调地址。

LinuxDo 的可用性以渠道后台实际要求为准；若允许 HTTP/IP 回调，可先用当前 80 端口验证，再切正式域名。

## 9. 排障

| 现象 | 排查 |
| --- | --- |
| 登录页没有第三方按钮 | `sys_auth_provider.status` 不是 `active`，或 `provider_type` 没有对应实现 |
| 回调 `oauthError=state_expired` | 授权超过 5 分钟、Redis 被清、或回调域名与发起域名不一致导致 state 丢失 |
| `oauthError=not_bound` | 外部身份未绑定任何账号；先密码登录后绑定 |
| `oauthError=portal_not_allowed` | 该外部身份只绑了家长/学生账号，网页端不签发；请用小程序 |
| `oauthError=exchange_failed` | 查看后端日志：client_id/secret、redirect_uri 是否与渠道后台一致，token/userinfo 端点是否可达 |
| 绑定后仍提示未绑定 | `sys_user_identity` 里没有对应 `(provider_code, app_type, open_id, user_id)`；检查回调日志与 state 的 userId |
| 登录操作日志渠道为空 | 确认接口走了 `@OperateLog(actionType=LOGIN)` 且控制器写入了 `AuthLoginAttributes.PROVIDER` |
| 选账号/换票 500，日志 `ERR unknown command 'GETDEL'` | 服务器 Redis 低于 6.2。代码已改用 Lua `GET`+`DEL` 消费票据（`ThirdPartyLoginService#take`），若仍出现说明跑的是旧包，重启后端即可；不建议为此升级 Redis |
