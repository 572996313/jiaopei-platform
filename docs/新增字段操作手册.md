# 新增字段操作手册

本文把「给系统加一个字段」拆成一条可以照着走的纵切流程。加字段从来不是只写一条 `ALTER TABLE`：
数据库、实体、接口、页面、字典展示少一环，就会出现「库里有了但页面没有」「页面有了但字典查不到」的半成品。

配套的自动门禁是 `backend/app/src/test/java/com/cornerstone/architecture/MigrationScriptGuardTest.java`：
新增迁移（app 侧 V119 起、core 侧 V121 起）缺注释、缺排序规则、用了禁项都会直接把测试打红。
门禁兜底，但门禁只看得见脚本，看不见实体和页面，所以流程仍要人走。

---

## 0. 先判断：真的需要新字段吗

很多需求看起来是「加个字段」，其实是别的形态。先过一遍这张表，能省掉一次迁移：

| 需求形态 | 更合适的做法 |
| --- | --- |
| 固定几个取值（状态、类型、渠道） | 加字典类型/字典项（`sys_dict_type` / `sys_dict_item`），字段存编码 |
| 运维要能改的开关、阈值、文案 | 系统参数（`sys_system_config`） |
| 只用于展示的派生值（应收、实收、余额、完成度） | Service 现算，不落库；落库就会和明细两本账（参考 V99 收费台账的派生值口径） |
| 需要查询、排序、统计、留历史快照 | 才落库加字段 |

落库前再确认三件事：

1. **语义归属**：这是业务字段还是底座通用字段？底座表只接受跨行业通用字段；教培语义（收费、课次、班级）必须留在业务模块，不能为了省事加到 `sys_` 表。
2. **是否参与算账**：参与金额、课时、完成度计算的字段，必须同步改计算引擎并补单测，不能只存不用。
3. **历史数据怎么办**：新字段对存量行是「默认值」还是「需要回填」？回填规则写进迁移或单独的数据修复脚本，并在变更单里写清。

## 1. 判断归属：迁移走单轨还是双轨

| 表的位置 | 迁移目录 | 要求 |
| --- | --- | --- |
| 底座表（`sys_*`） | `backend/cornerstone-core/src/main/resources/cornerstone/migration/` + `backend/app/src/main/resources/db/migration/` | 两份脚本**正文逐字一致**，版本号可以不同（例：V118 与 V120）。core 侧随 jar 发给下游，app 侧给教培现场执行 |
| 业务表（`jp_*`、`schedule_*`、`oper_log` 等） | `backend/app/src/main/resources/db/migration/` | 单轨，只写 app 侧 |

判断口诀：**这张表会不会原样出现在下游项目的库里？** 会，就是底座表，走双轨；只在教培业务里存在，就单轨。

权限码通常不需要新增：字段本身不产生新接口。只有新增菜单/按钮才按 AGENTS.md「权限码与菜单节点的分配规则」加，并且**新权限码要重新登录才生效**（JWT 快照在 Redis 里）。

## 2. 先填一张字段变更单

提交前把这张表填完，评审时对着看，比口头说清楚：

| 项目 | 填写内容 |
| --- | --- |
| 表名 / 字段名 | `jp_fee_ledger_item` / `discount_amount` |
| 中文名与业务口径 | 优惠金额（元），应收 = 收费月数 × 月标准 − 上期结余 − 其他抵扣 − 优惠金额 |
| 类型 / 是否可空 / 默认值 | `DECIMAL(12,2) NOT NULL DEFAULT 0.00` |
| 是否索引 / 唯一 | 普通字段，不建索引 |
| 是否参与计算 | 是，改 `FeeBillingEngine` 与台账明细应收公式 |
| 存量回填 | 全部按 0 处理，无需回填 |
| 影响页面 | 台账明细列表、台账编辑弹窗、导出矩阵、数据字典 |
| 兼容性 | 普通 `ALTER TABLE ADD COLUMN`，MySQL 8.x |

## 3. 迁移脚本：永远新增，不改历史

### 3.1 基本规则

- **已执行过的脚本一个字符都不许改**：Flyway 校验 checksum，改了生产直接拒绝启动。要修只能新增迁移。
- 版本号取当前最大值 +1（app 与 core 各自数各自的）。
- 一条语句一条路径，不写 `PREPARE` / 动态 SQL；半实施恢复办法写在脚本尾部注释里。
- 不用 CTE、窗口函数、`JSON_TABLE`、`IF()` 函数；不用 MariaDB 的 `ADD COLUMN IF NOT EXISTS`。
- 建表和加字符列都显式 `COLLATE=utf8mb4_unicode_ci`，不能只写 `DEFAULT CHARSET=utf8mb4`。
- 表注释、列注释必须有；枚举/布尔在注释里给码值对照。

### 3.2 加列模板

```sql
-- V119: 台账明细增加优惠金额。
-- 兼容自查：普通 ALTER TABLE，无 CTE/窗口/JSON_TABLE/IF()；字符列无（本列为 DECIMAL）。
-- 半实施恢复：若本脚本中断，确认 discount_amount 是否已存在，已存在则注释掉该句后手工续跑。
ALTER TABLE `jp_fee_ledger_item`
    ADD COLUMN `discount_amount` DECIMAL(12,2) NOT NULL DEFAULT 0.00
        COMMENT '优惠金额(元)' AFTER `other_deduction`;
```

### 3.3 建表模板

```sql
CREATE TABLE `jp_demo` (
  `id` bigint NOT NULL COMMENT '主键ID',
  `institution_id` bigint NOT NULL COMMENT '机构ID(多租户隔离)',
  `name` varchar(64) COLLATE utf8mb4_unicode_ci NOT NULL COMMENT '名称',
  `status` varchar(16) COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT 'active' COMMENT '状态(active=启用,disabled=停用)',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `created_by` bigint DEFAULT NULL COMMENT '创建人ID',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `updated_by` bigint DEFAULT NULL COMMENT '更新人ID',
  `deleted` tinyint(1) NOT NULL DEFAULT '0' COMMENT '逻辑删除标识(0=未删除,1=已删除)',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_jp_demo_name` (`institution_id`,`name`,`deleted`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='演示表';
```

### 3.4 索引与唯一键

- 逻辑删除表的唯一键**必须包含 `deleted`**，否则删掉一条就再也建不回同名记录。
- 如果「删除后重建同键」要支持多次，光靠 `deleted` 只能容一个墓碑，需要在删除入口改成「先查引用，无引用才物理删除」（V99 的收费项目就是这么做的）。
- 加唯一键/索引前确认它不会破坏外键依赖的最左前缀，否则先 `DROP FOREIGN KEY` 再调。

### 3.5 大表与锁

线上大表加列前先看行数。MySQL 8 的 `ADD COLUMN` 在满足条件时可走 instant/inplace，但**不要自行假设**：
在预发或与生产同版本的库上 `EXPLAIN`/实测耗时，必要时拆到停服窗口执行；脚本里不要写 `ALGORITHM=` 强指定，现场版本行为不一致时反而更难排。

## 4. 后端：从实体到服务

按依赖顺序改，避免编译到一半：

### 4.1 实体

位置：`backend/<模块>/src/main/java/.../domain/entity/XxxEntity.java`

```java
/** 优惠金额(元)。 */
private BigDecimal discountAmount;
```

- 列名默认按驼峰转下划线；只有名字对不上时才写 `@TableField("...")`。
- 类型与库里保持一致：金额 `BigDecimal`、时间 `LocalDate` / `LocalDateTime`、布尔用 `Boolean`。
- 该字段如果只是查询拼接用的临时列，写 `@TableField(exist = false)`，不要让它参与插入更新。

### 4.2 请求 / 视图 DTO

位置：`.../dto/`

- 请求字段加校验注解与中文消息；金额类用 `@Digits`，不要用 `double`。
- 每个字段写 `@Schema(description = "...")`，与 SQL COMMENT 用同一句中文，避免「表里一个说法、接口里另一个说法」。
- 前端按 `id` / `*Id` / `*Ids` / `*By` 命名自动把 16 位以上数字转字符串，所以 ID 字段名要遵守这个模式，否则跨端会丢精度。
- 字段有下划线别名时加 `@JsonAlias("discount_amount")`，保持与前端历史字段兼容。

### 4.3 Service

- 新字段的默认值、边界、非法值校验放在 Service，不要指望数据库默认值兜住所有入口。
- 参与派生计算的，改 `FeeBillingEngine` 等计算类，并补对应单测；只加字段不改引擎，页面金额会对不上。
- 涉及多表写入的，确认事务边界与并发兜底（唯一键 + 捕获 `DuplicateKeyException`，不要先查后插当唯一保障）。

### 4.4 Mapper / XML

- 用 `BaseMapper` 的常规 CRUD 不用改。
- 自定义 SQL / resultMap 要同步加列，否则查询结果里永远没有这个字段。
- 导出（Excel/矩阵）如果在 SQL 里写死了列，也要一起改。

## 5. 前端：列表、表单、详情三处都要看

| 落点 | 要做的事 |
| --- | --- |
| API 类型 | `frontend/packages/<模块>/src/api/*.ts` 的请求/响应类型加字段 |
| 列表 | 列定义、列宽、空值展示；配置化页面改 `sys_list_config` 的 `page_json` |
| 表单 | 新增/编辑弹窗加输入项、校验规则、默认值 |
| 详情/导出 | 详情抽屉、打印、导出矩阵是否要展示 |
| 字典/枚举 | 有码值的字段用字典项渲染，不要在前端写死中文 |

注意：

- 金额展示统一走现有格式化函数，不要在模板里手拼 `toFixed`。
- 新字段如果是可空，列表要能区分「0」和「未填」。
- 前端构建会做 `vue-tsc` 类型检查，API 类型不加会直接编译失败，这算一道天然门禁。

## 7. 常见问题速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 数据字典页看不到新列 | 迁移没执行 / 列没有 COMMENT | 看启动日志 Flyway；补 `MODIFY COLUMN` 注释（定义必须与原列一致） |
| 页面显示 `undefined` / `null` | 实体或 DTO 漏字段，或列名映射不对 | 对照实体、resultMap、前端类型三处 |
| 生产启动报 checksum mismatch | 改了已执行过的迁移 | 还原脚本，新增修复迁移 |
| 生产 1064 | 用了 `IF(`、MariaDB 方言，或用 `mysql -e` 传中文 COMMENT | 改 `CASE WHEN`；用文件喂入并带 `--default-character-set=utf8mb4` |
| 删除后重建同名记录报唯一键冲突 | 唯一键没带 `deleted`，或墓碑只容一个 | 唯一键补 `deleted`；删除入口改物理删除或加墓碑序号 |
| 前端 ID 末位变 0 | 字段名不符合 `id/*Id/*Ids/*By` 模式 | 改字段名或显式按字符串处理 |
| 新权限码不生效 | JWT 权限快照未刷新 | 重新登录 |
| 加列后旧数据是 0 但业务期望别的值 | 只给了数据库默认值，没做回填 | 补数据回填迁移或一次性修复脚本 |

## 8. 附：完整示例（给台账明细加「优惠金额」）

> 下面是示例，不要直接执行；真正落地时按当时的版本号和业务口径调整。

**迁移** `backend/app/src/main/resources/db/migration/V119__add_fee_ledger_item_discount.sql`

```sql
ALTER TABLE `jp_fee_ledger_item`
    ADD COLUMN `discount_amount` DECIMAL(12,2) NOT NULL DEFAULT 0.00
        COMMENT '优惠金额(元)' AFTER `other_deduction`;
```

**实体** `FeeLedgerItemEntity`

```java
/** 优惠金额(元)。 */
private BigDecimal discountAmount;
```

**请求** `FeeLedgerItemRequest`

```java
@Schema(description = "优惠金额(元)")
@JsonAlias("discount_amount")
@Digits(integer = 12, fraction = 4, message = "优惠金额最多 12 位整数、4 位小数")
BigDecimal discountAmount,
```

**视图** `FeeLedgerItemView`

```java
@Schema(description = "优惠金额(元)") BigDecimal discountAmount,
```

**Service**：`upsertItem` 里 `entity.setDiscountAmount(FeeBillingEngine.money(request.discountAmount()))`，
并检查应收公式是否要同步扣减；补 `FeeBillingEngineTest` 或对应 Service 单测。

**前端**：`frontend/packages/module-education/src/api/fee.ts` 加字段，
`FeeLedgerView.vue` 列表与 `FeeLedgerDialog.vue` 表单加录入项与展示。

**验收**：迁移门禁绿、后端测试绿、前端 build 绿、数据字典页能看到「优惠金额(元)」。
