# 列表配置使用教程(新手向)

> 目标读者:不懂前端、不会写 JSON 的产品 / 运营 / 运维同学。
> 这份文档教你用「系统设置 → 列表配置」把系统的列表页面(表格列、筛选、按钮、弹窗)改造成你想要的样子,
> **不用改代码、不用发版,保存立即生效**。

---

## 1. 这个功能是什么?

系统里的很多页面(如「用户管理」「角色管理」「系统参数」)长这样:

```
┌────────────────────────────────────────────────────────┐
│ 用户管理                              [关键字搜索▼][状态▼] │
│ [+ 新增用户]                                          │
│ ┌─────────┬─────────┬───────┬──────┬──────┬────────┐  │
│ │ 账号     │ 显示名称 │ 机构  │ 角色 │ 状态 │ 操作    │  │
│ ├─────────┼─────────┼───────┼──────┼──────┼────────┤  │
│ │ admin   │ 管理员  │ …     │ …    │ 启用 │ 编辑…  │  │
│ └─────────┴─────────┴───────┴──────┴──────┴────────┘  │
└────────────────────────────────────────────────────────┘
```

传统做法:整个「显示哪几列、上面有哪些筛选、有哪些按钮、弹窗长什么样」都写死在代码里,
想改任何一点都要找程序员改代码、重新发版。

「列表配置」把这个过程变成了**配置**:

| 你改这里(配置) | 页面效果 |
|---|---|
| 表格列(columns) | 表格显示哪几列、每列标题、宽窄、怎么渲染 |
| 查询条件(query) | 列表上方有哪些筛选框 |
| 按钮(actions) | 页面上有哪些操作按钮 |
| 弹窗表单(form) | 点新增/编辑时,弹窗里有哪些输入项 |
| 页面显示(page) | 页面标题、说明、计数文案 |
| 弹窗显示(dialog) | 弹窗宽度、标题、按钮文案 |

在「列表配置」里选一条 → 点「编辑」,有 **表单编辑(推荐)** 和 **JSON 编辑** 两种方式。
**新手全程用「表单编辑」即可,不需要手写 JSON。**

> 系统设置里的「用户管理 / 角色管理 / 系统参数」三个页面就是内置配置搭起来的,
> 你可以点开它们的「编辑」看看真实配置长什么样。

## 2. 快速上手:复制改(推荐)

最不容易出错的上手方式:复制一条现成的配置修改。

1. 打开「系统设置 → 列表配置」。
2. 点「新增配置」。
3. 在弹窗顶部的「从现有配置复制」下拉里,选一条最像的(比如要做用户列表就选「用户管理」)。
4. 点「复制」——这条配置的全部内容会搬进编辑框。
5. 改一下:资源编码(必填,如 `my-users`)、资源名称、分页接口路径(必填,如 `/system/users/page`,要问后端要)。
6. 按下面的各区块说明,增删改列、查询、按钮。
7. 点「创建配置」,回到页面刷新即可看到效果。

> 资源编码(resourceCode)是这条配置的唯一标识,创建后不可修改。它要和页面上的 `resource-code`
> 对上,页面才能用上这条配置(一般由开发者在页面里写死,或按命名约定)。

## 3. 各区块怎么填

### 3.1 表格列(columns)—— 表格显示哪几列

每个「卡片」就是表格的一列。**必填只有两个**:

| 字段 | 填什么 | 例子 |
|---|---|---|
| 数据字段名 prop | 这一列显示后端返回的哪个字段(必须和后端字段名完全一致,写错这列就空白) | `username`、`status` |
| 列标题 label | 表头显示的中文 | `账号`、`状态` |

其余都是可选:

| 字段 | 含义 | 例子 |
|---|---|---|
| 渲染类型 type | 这一列怎么显示。普通文字不用选;日期选 `datetime`;要彩色的状态标签选 `dict` | `datetime` / `dict` / `boolean` / `map` |
| 固定宽度 width | 固定列宽(像素),省得自适应 | `150` |
| 最小宽度 minWidth | 列最小宽度 | `140` |
| 超出省略 | 内容太长时显示 `…`,鼠标放上去看全文 | 开关 |
| 字典类型 dictType | 选 `dict` 后必填:哪个字典来翻译值 | `common_status`(启用/停用) |
| 标签颜色 tagTypeMap | 选 `dict` 后可选:每个值显示什么颜色 | `active` → 绿色(success)、`disabled` → 灰色(info) |
| 是/否文案 | 选 `boolean` 后显示 | `是` / `否` |
| 值映射 valueMap | 选 `map` 后必填:把后端值翻译成中文 | `auth` → `认证` |
| 自定义渲染器 renderer | 特殊列才用(机构名、权限标签等),普通列**不要填** | `institutionName` 等 |

**常用场景:状态列显示彩色标签**

1. 列类型选 `dict`。
2. 字典类型填 `common_status`(启用/停用这个字典)。
3. 在「标签颜色映射」里加行:`active` → `success`(绿)、`disabled` → `info`(灰)。

### 3.2 查询条件(query)—— 列表上方的筛选

每个「卡片」是一个筛选框。**必填两个**:

| 字段 | 填什么 | 例子 |
|---|---|---|
| 查询参数名 field | 筛选后传给后端的参数名(必须后端接口支持,否则填了不生效,问后端要支持哪些) | `keyword`、`status` |
| 标签 label | 筛选框前的文字 | `关键字`、`状态` |

可选:

| 字段 | 含义 | 例子 |
|---|---|---|
| 控件类型 type | 输入框 / 下拉 / 字典下拉 / 日期 | `input`(默认) |
| 占位提示 placeholder | 框内的灰色提示 | `请输入账号` |
| 默认值 defaultValue | 一进页面默认带上的值 | `active` |
| 选项来源 | 下拉类控件:手填选项(值+文案)或选现成数据源 | 底座内置:`institutions`(机构)/ `roles`(角色)/ `status`(启用/停用);其余编码(如 `campuses`)在「数据源配置」里维护,下拉支持直接输入编码 |
| 字典类型 dictType | 选「字典下拉」后必填 | `common_status` |

### 3.3 按钮(actions)—— 页面操作入口

每个「卡片」是一个按钮。**必填两个**:

| 字段 | 填什么 | 例子 |
|---|---|---|
| 动作名 action | 点击后触发哪个动作(由页面代码注册,**写错按钮不显示**,照着该页面已有按钮填) | `user-create`、`role-delete` |
| 按钮文案 label | 按钮显示文字 | `新增用户` |

可选/推荐:

| 字段 | 含义 | 例子 |
|---|---|---|
| 位置 position | 表格上方工具栏(`toolbar`)/ 行内操作列(`row`) | `toolbar` |
| 样式 buttonType | 按钮颜色风格 | `primary`(蓝)/ `danger`(红)/ `text` / `default` |
| 权限码 permission | 谁有权限看到/点这个按钮;不选=所有人都能看 | `system:user:manage` |
| 点击行为 actionType | 点击后默认干什么;不填会自动按动作名推断 | `create` / `edit` / `delete` / `toggle-status` |

**注意**:删除、启停等复杂按钮通常附带确认弹窗、禁删条件等,这些由页面代码里的
「动作处理器」负责。配置里只负责声明「有哪些按钮、文案和样式」。

### 3.4 弹窗表单(form)—— 新增/编辑弹窗里的输入项

顶部「弹窗表单整体设置」:

| 字段 | 含义 |
|---|---|
| 栅格列数 gridColumns | 一行放几个字段,默认 2 |
| 标签宽度 labelWidth | 字段标题的宽度,如 `100px` 或 `auto` |

下面每个「卡片」是弹窗里的一个输入项。**必填三个**:

| 字段 | 填什么 | 例子 |
|---|---|---|
| 字段名 field | 保存接口的字段名(与后端一致,写错保存时会丢字段) | `displayName` |
| 标签 label | 弹窗里显示的文字 | `显示名称` |
| 控件类型 type | 用哪种控件 | `input`(输入框)/ `select`(下拉)/ `switch`(开关)/ `radio` … |

常用可选:

| 字段 | 含义 |
|---|---|
| 必填 required | 打开后不填不能提交 |
| 占位提示 placeholder | 框内灰色提示 |
| 提示文字 tip | 字段下方灰色说明 |
| 栅格占位 gridSpan | 占半行 `1` / 整行 `2` |
| 默认值 defaultValue | 新增弹窗打开时的初始值 |
| 选项来源 | 下拉/单选/多选:手填选项或引现成数据源(同查询条件) |
| 仅新增/编辑显示、禁用 | 控制这个字段在新增弹窗还是编辑弹窗出现/可改 |

**注意**:一个配置如果没配弹窗表单,点击页面上「新增/编辑」按钮时会提示
「请先在列表配置中配置弹窗表单」。

### 3.5 页面显示(page)—— 说明与空态文案

| 字段 | 含义 | 默认 |
|---|---|---|
| 说明 description | 表格上方一行小字,只写「怎么生效」这一类 | 不显示 |
| 空数据文案 emptyText | 表格没数据时显示 | `暂无数据` |

页面大标题与「共 X 条」计数已从配置里移除:页头显示的就是菜单名,卡片标题只在"一页多表"时用于区分;
条数由分页器承担,不分页的小表不显示条数。

### 3.6 弹窗显示(dialog)—— 弹窗外壳

| 字段 | 含义 | 默认 |
|---|---|---|
| 弹窗宽度 width | 新增/编辑弹窗宽度 | `640px` |
| 新增标题 createTitle | 新增弹窗标题 | `新增{资源名}` |
| 编辑标题 editTitle | 编辑弹窗标题 | `编辑{资源名}` |
| 提交/取消按钮文案 submitText / cancelText | 弹窗底部按钮文字 | `保存` / `取消` |
| 成功提示 createMessage / updateMessage | 操作成功后的提示文字 | `{资源名}已创建` / `已更新` |
| 提交后刷新列表 | 提交成功后是否重拉列表 | 开 |

## 4. 常见问题(Q&A)

**Q:我加了列,保存了,为什么页面没变化?**
A:先确认三点:① 保存后是否刷新了页面(配置走缓存,强刷或重进页面);② `prop` 是否与后端返回字段名完全一致;③ 这条配置的 `resource_code` 是否与页面引用的资源编码一致。

**Q:我加了个筛选,后端没反应/不生效?**
A:查询条件 `field` 必须被后端分页接口支持。不知道支持哪些就问后端
(一般有 `keyword` / `status` / `institutionId` 等固定几个)。

**Q:我加的按钮不显示?**
A:`action`(动作名)必须与页面代码里注册的动作处理器一致。抄同页面已有按钮的动作名最保险;权限不足也会隐藏。

**Q:改坏了、页面打不开了怎么办?**
A:每条配置都可「编辑 → JSON 编辑」直接改回,或「停用」让页面回退到默认(甚至可删除重来)。
三种内置配置(id 1-3)不能删,但可以停用。

**Q:这个配置我可以建多个页面吗?**
A:可以。一条配置 = 一个列表页。为每个页面建一条配置,资源编码唯一即可。
