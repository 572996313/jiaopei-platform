# 前端交付说明

> 本文档描述**当前形态**的前端工程：pnpm workspace 多包架构、真实登录鉴权、全量真实接口。
> 早期"骨架页/占位页"阶段的描述已全部清除；生产部署细节以 `docs/生产部署说明.md` 为准，本文只留前端相关口径。

## 1. 工程架构（阶段三起的 pnpm workspace）

`frontend/` 根目录即**壳工程**（`index.html`、`vite.config.ts`、`src/` 原位），业务代码拆为 workspace 包：

| 包 | 包名 | 内容 | 依赖方向 |
| --- | --- | --- | --- |
| `packages/core/` | `@cornerstone/core` | 底座：登录/注册/激活/改密、系统管理全套页面、`ConfigurableCrudPage` 脚手架、`AppLayout`、扩展点注册表、`api/http.ts` 等公共设施 | 不依赖任何业务包 |
| `packages/module-organization/` | `@cornerstone/module-organization` | 业务：校区/教室/学期/时间段/时间段模板页面 + `educationScope` 范围筛选 store | → core |
| `packages/module-education/` | `@cornerstone/module-education` | 业务：教师/学员/班级/课程（含分类与班型）/排课/课表/考勤页面 | → core、→ organization |
| `frontend/src/`（壳） | — | `main.ts`、`router/index.ts`、装配清单 `modules.ts`、跨模块工作台 | → 上面三块 |

要点：

- **源码级引用，不单独构建各包**：vite `resolve.alias` + tsconfig `paths` 把 `@cornerstone/*` 直指 `packages/*/src`（`@` 别名必须排在最后）。新增包要同时改这两处。
- **包间导入一律写全包名**（如 `@cornerstone/core/api/http`），`@/` 只允许出现在壳工程；由 `eslint.config.js` 的 `no-restricted-imports` 分块强制，写错 `pnpm lint` 直接报错。
- **装配清单 `frontend/src/modules.ts` 两件事必须同时成立**：① import 模块入口（扩展点注册是 import 副作用）；② 模块路由清单进 `projectChildRoutes`。只留底座时删掉这两处条目即可，构建产物不含任何业务 chunk。
- **扩展点**（`packages/core/src/extension/module-extensions.ts`）：`registerListRenderer`（列表渲染器）、`registerPermissionLabels`（权限码中文名）、`registerNavItems`（**只登记没有菜单节点可挂的落地页**，如工作台；侧边栏的组与页面自 2026-09-29 起直接由 `sys_menu` 生成，见 3.4）、`registerBranding`（品牌与登录页文案）、`registerPageSlot` + `onPageRefresh`（页面插槽注入，能力保留给"把业务卡片挂进别的模块页面"这类需求；本仓库自 V85 起课程/课程分类/班型已从校区页独立成 `/courses` 页、V87 又把班型拆到 `/class-types`，**当前没有任何使用方**）、`registerInvitationActions`（注册凭证页行操作，education 包据此注入「小程序码」按钮）。新增业务页面/按钮改的是模块入口，不动 core。
- 底座包同时以 `@cornerstone/core` npm 包发布到私服 Verdaccio 供下游项目（achievement）使用；**本仓库自身走 workspace 源码，不依赖已发布包**。

## 2. 常用命令（工作目录 `frontend/`）

```bash
pnpm install
pnpm dev          # 127.0.0.1:5173，/api 代理到 127.0.0.1:8080
pnpm build        # vue-tsc 类型检查 + vite build
pnpm lint         # ESLint（flat config）
pnpm lint:fix
pnpm format       # Prettier（src/ 与 packages/）
pnpm preview
```

无单测脚本；`pnpm build`（类型）+ `pnpm lint`（规范）构成前端门禁。

> **档案类下拉一律服务端按需搜索，页面不持有全量数组**：班级走 `views/components/ClassSelect.vue`（单值）/ `ClassMultiSelect.vue`（多选）、学员走 `StudentSelect.vue`，接口是 `GET /api/education/{classes|students}/options`——`keyword` 模糊匹配名称与编码、班级可选地带 `campusId`/`termId` 收窄（学员档案自 V89 起不持有校区，`StudentSelect` 因此没有 `campusId` prop，"这个校区的学员"要靠班级筛）、**服务端 `LIMIT 30` 封顶**（本机实测班级 279 条、学员 3583 条时，全量 `el-option` 会让整页卡数秒）。**已选项的名称不走 prop**：`composables/classLabels.ts` / `studentLabels.ts` 各持一份模块级「id → 显示名」缓存，组件拉到选项时写入，表格行只有 id 时由视图调 `ensureClassLabels(institutionId, ids)` 批量回查（`/classes/options?ids=1,2,3`，上限 200，传了 ids 后端忽略 `keyword`）；查不到就显示 `班级 #id`，不硬猜也不留空。新增档案类下拉照这套抄，不要写 `fetchXxxList()` 拉全量。

> **排课术语**：界面上的「周期排课计划」（工具栏入口「周期计划」，后端资源 `schedule-plans`、表 `jp_schedule_plan`）只描述「哪个班、每周固定哪几个节次」，是批量生成课次的节奏模板；「每班每周应上几节」是**班级课时目标**（`jp_class.weekly_lessons`，在班级档案里维护），两者是两件事。完成度报表优先按课时目标算分母（设了目标的班，"计划都排上了但一周只上两节、目标是三节"照样报缺），未设目标才回落到计划展开；行上的分母来源会把口径直接写出来（`按计划展开` / `按课时目标 N 节/周`），不要让人猜。
> **软提示的交互**：教师超周/日课时上限、学员跨班撞课、课次落在停排日都只提示不拦。手工课次弹窗（`ScheduleLessonFormDialog`）第一次点保存只把这些 `notices` 摆出来、按钮不禁用，再点一次即放行；批量向导在预览页把它们单独一个黄色告警块列在冲突表上方，与红色的硬冲突行分块。硬冲突（班级/教室/教师同时段占用、命中启用中的禁排规则）一律拦。
> **排课规则的三种对象**：`target_type` 现有 class/teacher/classroom，编辑器（`ScheduleRuleEditorDialog`）的对象下拉与目标选择器随之多一条"教室"（走 `campuses`/教室数据源），列表弹窗的目标列显示教室名。**校区日历（停排日）不是规则**：它在规则列表弹窗里是并列的另一张卡片（`SchoolCalendarPanel`），按年份列日子、可增删，只影响提示不影响已生成课次。
> **新建只有一个入口**：周期计划与排课规则同口径，工具栏只放"打开列表弹窗"的入口，**新建按钮在弹窗内**（`周期计划 → 新建计划`），不许再加第二个工具栏新建按钮——曾经两处都有，操作员反而找不到。改这类文案要同步三处：`ScheduleManageView` 工具栏、两个计划弹窗、`ScheduleCompletenessView` 的口径说明（里面有"去 X 补排"的按按钮名引用）。
> **自动补排（`ScheduleAutoFillDialog`）**：入口在完成度页的工具栏「一键补排」（按 `education:schedule:write` 显隐，报表本身只要读码），弹窗两个页签——「缺口补排」先选**弹窗自己的校区与学期**（页面顶部那三个是可选筛项，按「新增弹窗的必填上下文由弹窗自身表单承担」的口径不借它；只有一个候选时自动定上），再填窗口/班级/择优策略后先 `/preview` 出草案表（补在哪天哪节、落点是计划格子还是任意空位、教师与教室），草案下方单独一张「补不上的」表按班级给出中文原因；点「执行补排」前有二次确认，写明将生成几节、之后可在「批次清单」整批撤销。班级多选（`ClassMultiSelect`）按弹窗里选的校区走 `/education/classes/options` 服务端搜（一次 30 条，不选=本校区全部有缺口），**只按校区筛、不按学期筛**（服务端也只校验班级归属校区；一旦按学期过滤，学期留空的班级就会从候选里消失）。「批次清单」只显示当前校区最近 20 个批次（换弹窗里的校区即换范围），撤销按返回体原话提示（删了几节、留了几节、为什么留）。**补排窗口不给"不限"，默认今天起 27 天**：引擎不往今天之前排课，起点早于今天会被服务端拒。执行成功后草案自动清空，不会留一份旧表让人误以为还能接着点。**预览与执行是各算一遍引擎**（不是拿草案去落库），所以确认到执行之间若有人手工插了一节课，以执行为准。

### 3.4 侧边导航分组

侧边栏的顶层组**由 `sys_menu` 的顶层节点直接生成**（2026-09-29 起）：组名取节点的 `menu_name`、组间顺序取 `sort_no`、图标取 `icon`，组内页面与顺序取它的子节点，全部按当前用户**已授权**的菜单树裁剪。`registerNavItems` 只剩一种用途——登记**没有菜单节点可挂的落地页**（工作台），业务包不再登记导航项。

- **一个目录 = 一组**（V92 定稿，此前每拆一页就往顶层铺一个散页、十二个图标一次铺满）：新页面要么进已有目录、要么另建目录节点。组名与组内顺序都在库里，后台改名/改序/换图标即生效——**不再有前端那份 `groupOrder`/`prefixes` 登记表**（它正是"客户调了 `sort_no`、界面不动"的根因）；完整导航在"单项目录自成一组"时不再重复渲染组标题（`AppLayout` 的 `isGroupTitleRedundant`，窄栏浮层早有同一条判断）。**组顺序按"多久用一次"排**：每天上课点名在前，每周排课与招生居中，开班前配好就不常进的资料垫底。
- **客户自助调导航走「导航编排」页**（`/system/navigation`，节点 140，权限 `system:nav:manage`，教培 V93 / core V111 双轨种子）：交付后运维自己改组名、换图标、调顺序、把页面挪进别的分组，不用改代码也不用发版。这一页是 `sys_menu` 的**受限视图**，只有五列可写；路由、权限码、类型、编码仍归「菜单管理」（平台管理员）。三处刻意的取舍：**目录不给"侧边栏可见"开关**（`buildTree` 会把父节点未授权的子节点提升到根，藏目录等于把它下面的页面炸成一排散页图标）、**「系统设置」整棵子树只读**（用户管理/角色管理/机构资料后端还没比机构范围，挪进业务分组等于绕过 AGENTS「安全与数据一致性约定」第 8 条）、**新建分组立即写库并同事务授权给所有在职角色**（页面要先拿到真实 id 才能往里挪东西；漏授权的表现是整组入口消失且不报错），「菜单管理」手工建目录仍然不自动授权，别把两处当成一回事。顶层入口**不许同名**（两颗一样的图标等于白改），保存是整批校验通过才落库，结构改动**不踢会话**（导航树每次进系统现拉，别人下次进入才看到）。
- **入口显隐由授权菜单树决定**：每个顶层节点与它的子节点都对应一个 `sys_menu` 节点，角色未勾选则入口不出现，侧边栏名与页签名取节点的 `menuName`，后台改名即生效。业务入口不再写 `alwaysVisible`（口径见 AGENTS.md「侧边栏导航」）。
  - **目录必须授权给所有该看见它的角色**（V81 给目录 130、V92 给目录 139 做的就是这件事，V92 还额外给"勾了子页却没勾父目录"的角色补了 15 与 130）：目录节点自己不带权限码，若某个角色没有它但勾了里面的页面，建树时该子节点会被**提升成根节点**，表现是"给了教室管理权限，导航里却什么都没有"。没有可见子节点的目录本身不渲染，所以全量授目录不会多出空入口。
- **权限码按节点性质分配（V62 / 底座 V105）**：系统管理页的码原先全压在「用户维护」这类按钮节点上、页面节点不带码，结果只勾页面的角色看得见入口、点进去整页 403。现在读与写共用单码的页面（`system:*:manage`）把码挂到**页面节点**上，同码的按钮节点已废弃；读/写成对的页面（`系统参数`→`system:config:read`、`机构资料`→`tenant:read`、`操作日志`→`system:operlog:read`）页面节点挂读码、写码仍留在按钮节点（`参数维护`、`机构资料维护`）。`功能权限`页不挂码——它两个接口仅需登录。完整口径见 AGENTS.md「权限码与菜单节点的分配规则」。
- **权限码中文名以登记表为权威**（core `constants/permissionLabels.ts` + 模块 `registerPermissionLabels`），菜单节点名只作兜底与"挂在哪"的说明：写码可以跨页面共用，拿首个节点名当码名会把 `education:profile:write` 显示成「教师档案」。**新增权限码必须同步登记**，否则下拉与总览页显示裸码。
- **功能权限总览页按"一个码一条链路"重排**（`/system/permission-overview`，只读）：统计卡四张为 生效权限码 / 受控接口 / **未挂菜单节点的码** / **未登记权限码**，后两张非 0 即配置缺口（对应 AGENTS.md 的自查项）。左栏仍是 `sys_menu` 三级树（目录只做折叠、页面与按钮行带权限码标签与该码接口数），右栏按 码本体 → 谁能用 → 挂在哪 → 管哪些接口 四段展开，接口清单支持方法过滤与"展开其余 N 条"。页内不提供编辑、不加页内大标题。**接口随之变了两处**：原 `permissions[].dangling`（悬空码）恒为 false 已删——卡列表只从注解扫描生成，有注解就必有接口，这个指标结构上不可能命中；`roles[]` 新增 `fromPreset`（角色预设权限 CSV 授予）与 `fromMenuNode`（勾选携带该码的菜单节点授予），用来提示"撤销要两边都撤"。
- **业务读取码已清零（V113）**：`education:read`/`organization:read`/`announcement:read` 不再存在，业务模块 GET 接口登录即可，机构/校区范围由服务层 `InstitutionScopeGuard`/`CampusScopeGuard` 兜住；页面节点 `permission_code` 留空，侧边栏可见性只由 `sys_role_menu` 决定（`currentUserMenus` 退化为纯节点过滤）。**好消息是不再需要"为了拿读取码去勾基础页"**：客户可以只勾收费台账、不勾班级/课程/教师等业务页，需要时再按页面补勾。**但「机构资料」页（节点 8，`tenant:read`）目前仍必须保留给所有业务角色**：`AppLayout` 启动时调 `GET /api/organizations/institutions` 填机构芯片，各业务页的 `institutionId` 也取自 `institutionStore.currentInstitutionId`；该接口还没做机构范围裁剪（任何持码者都能看到全库机构），码一撤就 403、业务页拿不到机构。把这条接口改成"平台管理员看全量、机构账号只看本机构、读取仅需登录"属下一批，V113 未包含。写操作仍是隐藏按钮节点（`organization_master_data_write` → `organization:write`，一个按钮覆盖校区与学期、校区默认账号、教室管理、时段模板、节次明细五页；`education_class_write` → `education:class:write` 覆盖班级档案与分班与名册两页，`education_profile_write` → `education:profile:write` 覆盖教师档案与学员档案两页，`education_catalog_write` → `education:catalog:write` 覆盖课程档案与班型档案两页），**都按页面域一条码、不按页再拆**，见 AGENTS.md 权限规则；`student_portal_access`/`parent_portal_access` → `miniapp:access`。授权弹窗勾页面时会把本页全部按钮节点一起授出（`RoleAuthorizationDialog.togglePage`），要只读角色再单独取消按钮即可。角色的预设权限与菜单授权取并集，撤销写码要两边都撤。
- 前端只做入口隐藏，**不加路由守卫**：直连 URL 的业务读取接口登录即可（V113），写操作仍由后端 `@RequiresPermission` 拦。也就是说"不勾页面"只挡侧边栏，不挡直连 URL 读数据；需要连读都不给的页面只能靠机构/校区范围或后续单独加码。

## 4. 联调注意事项

### 4.1 后端服务与代理

- Vite dev 地址 `http://127.0.0.1:5173`，`/api/**` 由 vite 代理到 `http://127.0.0.1:8080`（`vite.config.ts`）。
- 生产容器下同样保持 `/api/**` 同源，由前端 Nginx（`docker/nginx/default.conf`）反代到容器网络内 `backend:8080`；SPA 路由 `try_files` 回退，健康检查 `/healthz`。部署细节见 `docs/生产部署说明.md`。

### 4.2 鉴权

- 真实登录：`POST /api/auth/login` 返回 JWT，会话存 Redis；登录态持久化在 localStorage key `cornerstone.auth.session`（`core/src/utils/auth-session.ts`），`core/src/api/http.ts` 从该处取 `Authorization: Bearer <token>` 自动携带。
- `VITE_API_AUTHORIZATION` 仅作无登录态联调的兜底固定头，生产默认留空。
- 强制改密态用户除 `/api/auth/me`、`/api/auth/change-password` 外一律 401，路由守卫会导向改密页。
- 页面写操作按钮按权限码显隐（与后端 `@RequiresPermission` 同一套码：底座 `system:*`/`tenant:*`，业务 `organization:*`/`education:*`/`miniapp:access`）。

### 4.3 大 ID 字符串约定

- 雪花 ID 19 位超出 JS 安全整数。响应转换在 `core/src/api/http.ts` 的 `transformResponse` 里按**字段名模式**兜底：匹配 `id`、`*Id`、`*Ids`、`*By` 且值为 16 位以上数字的转字符串。**不需要维护字段白名单**（旧 `LARGE_ID_FIELDS` 机制已废弃）。
- 不按该模式命名的 16+ 位 Long 字段会被静默截断，新增此类字段需在前端显式处理。
- 前端全链路按字符串 ID 使用；请求侧后端 `FlexibleLongIdDeserializer` 数字/字符串都收。

### 4.4 请求与错误处理

- `core/src/api/request.ts` 统一解包后端 `ApiResponse`，`success=false` 或 HTTP 异常抛 `ApiError`；业务代码不手拼响应壳。
- 列表页优先使用 `ConfigurableCrudPage`/`ConfigurableList`（自带请求序列号守卫，切机构不竞态）。
- 机构/校区/学期范围筛选走 module-organization 的 `educationScope` store；切换机构后下拉数据源自动重载。

### 4.5 模块开关的前端表现

- 后端 `cornerstone.modules.enabled.*` 关闭某模块时，`/api/system/bootstrap` 的模块清单里不再列出该模块；前端导航与页面仍登记（装配是构建期的），接口调用会得到 404。裁剪形态在壳 `modules.ts` 摘条目 + 删依赖，见 AGENTS.md。
