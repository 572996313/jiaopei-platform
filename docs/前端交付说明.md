# 前端交付说明

> 本文档描述**当前形态**的前端工程：pnpm workspace 多包架构、真实登录鉴权、全量真实接口。
> 早期"骨架页/占位页"阶段的描述已全部清除；生产部署细节以 `docs/生产部署说明.md` 为准，本文只留前端相关口径。

## 1. 工程架构（阶段三起的 pnpm workspace）

`frontend/` 根目录即**壳工程**（`index.html`、`vite.config.ts`、`src/` 原位），业务代码拆为 workspace 包：

| 包 | 包名 | 内容 | 依赖方向 |
| --- | --- | --- | --- |
| `packages/core/` | `@cornerstone/core` | 底座：登录/注册/激活/改密、系统管理全套页面、`ConfigurableCrudPage` 脚手架、`AppLayout`、扩展点注册表、`api/http.ts` 等公共设施 | 不依赖任何业务包 |
| `packages/module-organization/` | `@cornerstone/module-organization` | 业务：校区/教室/学期/时间段/时间段模板页面 + `educationScope` 范围筛选 store | → core |
| `packages/module-education/` | `@cornerstone/module-education` | 业务：教师/学员/班级/排课/课表/考勤页面 + 课程/课程分类/班型主数据卡片 | → core、→ organization |
| `frontend/src/`（壳） | — | `main.ts`、`router/index.ts`、装配清单 `modules.ts`、跨模块工作台 | → 上面三块 |

要点：

- **源码级引用，不单独构建各包**：vite `resolve.alias` + tsconfig `paths` 把 `@cornerstone/*` 直指 `packages/*/src`（`@` 别名必须排在最后）。新增包要同时改这两处。
- **包间导入一律写全包名**（如 `@cornerstone/core/api/http`），`@/` 只允许出现在壳工程；由 `eslint.config.js` 的 `no-restricted-imports` 分块强制，写错 `pnpm lint` 直接报错。
- **装配清单 `frontend/src/modules.ts` 两件事必须同时成立**：① import 模块入口（扩展点注册是 import 副作用）；② 模块路由清单进 `projectChildRoutes`。只留底座时删掉这两处条目即可，构建产物不含任何业务 chunk。
- **扩展点**（`packages/core/src/extension/module-extensions.ts`）：`registerListRenderer`（列表渲染器）、`registerPermissionLabels`（权限码中文名）、`registerNavItems`（侧边栏业务入口）、`registerBranding`（品牌与登录页文案）、`registerPageSlot` + `onPageRefresh`（页面插槽注入，如校区页里的课程/课程分类/班型三张卡片来自 education 包）、`registerInvitationActions`（注册凭证页行操作，education 包据此注入「小程序码」按钮）。新增业务页面/按钮改的是模块入口，不动 core。
- 底座包同时以 `@cornerstone/core` npm 包发布到私服 Verdaccio 供下游项目（achievement）使用；**本仓库自身走 workspace 源码，不依赖已发布包**。

## 2. 常用命令（工作目录 `frontend/`）

```bash
pnpm install
pnpm dev          # 127.0.0.1:5173，/api 代理到 127.0.0.1:8080
pnpm build        # vue-tsc 类型检查 + vite build
pnpm lint         # ESLint（flat config）
pnpm lint:fix
pnpm format       # Prettier（src/ 与 packages/）
pnpm preview
```

无单测脚本；`pnpm build`（类型）+ `pnpm lint`（规范）构成前端门禁。

所有业务页面均已接真实接口，不再有"占位/骨架"形态。

> **排课术语**：界面上的「周期排课计划」（工具栏入口「周期计划」，后端资源 `schedule-plans`、表 `jp_schedule_plan`）只描述「哪个班、每周固定哪几个节次」，是批量生成课次的节奏模板，**不是**「每班每科每周应上几节」的课时目标——本系统目前没有课时目标实体，所以完成度报表只回答计划有没有落地。
> **新建只有一个入口**：周期计划与排课规则同口径，工具栏只放"打开列表弹窗"的入口，**新建按钮在弹窗内**（`周期计划 → 新建计划`），不许再加第二个工具栏新建按钮——曾经两处都有，操作员反而找不到。改这类文案要同步三处：`ScheduleManageView` 工具栏、两个计划弹窗、`ScheduleCompletenessView` 的口径说明（里面有"去 X 补排"的按按钮名引用）。

### 3.4 侧边导航分组

底座 `AppLayout` 只内置「系统设置」；其余入口由各包 `registerNavItems` 登记：

| 分组（groupOrder） | 条目 | 登记方 |
| --- | --- | --- |
| 工作台（10） | 今日教务 `/dashboard` | 壳 `modules.ts` |
| 日常教务（20） | 排课中心 `/scheduling`、报名与入班 `/students` | module-education |
| 班级与教学（30） | 班级学员 `/classes` | module-education |
| 档案中心（40） | 机构与教学资源 `/campus`、时间段设置 `/time-slots`（org）；教师档案 `/teachers`（edu） | 两模块共用该组 |

- **入口显隐由授权菜单树决定**：除工作台（落地页，无对应权限）外，每个条目都对应一个 `sys_menu` 页面节点，登记项以 `menuCode` 声明（排课中心这一组仍走 `menuCatalogCode`，子项来自目录）；角色未勾选该页面节点则入口不出现，侧边栏名与页签名取节点的 `menuName`，后台改名即生效。业务入口不再写 `alwaysVisible`（口径见 AGENTS.md「侧边栏导航」）。
- **权限码按节点性质分配（V62 / 底座 V105）**：系统管理页的码原先全压在「用户维护」这类按钮节点上、页面节点不带码，结果只勾页面的角色看得见入口、点进去整页 403。现在读与写共用单码的页面（`system:*:manage`）把码挂到**页面节点**上，同码的按钮节点已废弃；读/写成对的页面（`系统参数`→`system:config:read`、`机构资料`→`tenant:read`、`操作日志`→`system:operlog:read`）页面节点挂读码、写码仍留在按钮节点（`参数维护`、`机构资料维护`）。`功能权限`页不挂码——它两个接口仅需登录。完整口径见 AGENTS.md「权限码与菜单节点的分配规则」。
- **权限码中文名以登记表为权威**（core `constants/permissionLabels.ts` + 模块 `registerPermissionLabels`），菜单节点名只作兜底与"挂在哪"的说明：一个读码可以挂在多个页面节点上，拿首个节点名当码名会把 `education:read` 显示成「排课管理」。**新增权限码必须同步登记**，否则下拉与总览页显示裸码。
- **页面节点自带读取码**（V61 种子）：`organization_campus`/`organization_time_slots` → `organization:read`，`education_enrollments`/`education_classes`/`education_teachers` 与排课三页 → `education:read`，勾页面即给读码，不存在"入口看得见却整页 403"的中间态；写操作仍是隐藏按钮节点（`organization_master_data_write` → `organization:write`，`student_portal_access`/`parent_portal_access` → `miniapp:access`）。角色的预设权限与菜单授权取并集，撤销要两边都撤。
- 前端只做入口隐藏，**不加路由守卫**：直连 URL 由后端 `@RequiresPermission` 拦（与排课中心既有行为一致）。

## 4. 联调注意事项

### 4.1 后端服务与代理

- Vite dev 地址 `http://127.0.0.1:5173`，`/api/**` 由 vite 代理到 `http://127.0.0.1:8080`（`vite.config.ts`）。
- 生产容器下同样保持 `/api/**` 同源，由前端 Nginx（`docker/nginx/default.conf`）反代到容器网络内 `backend:8080`；SPA 路由 `try_files` 回退，健康检查 `/healthz`。部署细节见 `docs/生产部署说明.md`。

### 4.2 鉴权

- 真实登录：`POST /api/auth/login` 返回 JWT，会话存 Redis；登录态持久化在 localStorage key `cornerstone.auth.session`（`core/src/utils/auth-session.ts`），`core/src/api/http.ts` 从该处取 `Authorization: Bearer <token>` 自动携带。
- `VITE_API_AUTHORIZATION` 仅作无登录态联调的兜底固定头，生产默认留空。
- 强制改密态用户除 `/api/auth/me`、`/api/auth/change-password` 外一律 401，路由守卫会导向改密页。
- 页面写操作按钮按权限码显隐（与后端 `@RequiresPermission` 同一套码：底座 `system:*`/`tenant:*`，业务 `organization:*`/`education:*`/`miniapp:access`）。

### 4.3 大 ID 字符串约定

- 雪花 ID 19 位超出 JS 安全整数。响应转换在 `core/src/api/http.ts` 的 `transformResponse` 里按**字段名模式**兜底：匹配 `id`、`*Id`、`*Ids`、`*By` 且值为 16 位以上数字的转字符串。**不需要维护字段白名单**（旧 `LARGE_ID_FIELDS` 机制已废弃）。
- 不按该模式命名的 16+ 位 Long 字段会被静默截断，新增此类字段需在前端显式处理。
- 前端全链路按字符串 ID 使用；请求侧后端 `FlexibleLongIdDeserializer` 数字/字符串都收。

### 4.4 请求与错误处理

- `core/src/api/request.ts` 统一解包后端 `ApiResponse`，`success=false` 或 HTTP 异常抛 `ApiError`；业务代码不手拼响应壳。
- 列表页优先使用 `ConfigurableCrudPage`/`ConfigurableList`（自带请求序列号守卫，切机构不竞态）。
- 机构/校区/学期范围筛选走 module-organization 的 `educationScope` store；切换机构后下拉数据源自动重载。

### 4.5 模块开关的前端表现

- 后端 `cornerstone.modules.enabled.*` 关闭某模块时，`/api/system/bootstrap` 的模块清单里不再列出该模块；前端导航与页面仍登记（装配是构建期的），接口调用会得到 404。裁剪形态在壳 `modules.ts` 摘条目 + 删依赖，见 AGENTS.md。
