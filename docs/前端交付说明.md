## 4. 前端联调注意事项

### 4.1 后端服务与代理

- Vite 开发端口：`http://127.0.0.1:5173`
- 后端服务地址：`http://127.0.0.1:18080`
- 代理配置文件：`frontend/vite.config.ts`
- 当前代理规则：前端统一请求 `/api/**`，由 Vite 转发到 `127.0.0.1:18080`
- 生产容器托管入口：`docker/nginx/default.conf`
- 生产容器下仍保持 `/api/**` 同源访问，由前端 Nginx 反向代理到容器网络内的 `backend:8080`

### 4.2 鉴权头

- 默认鉴权头在 `frontend/src/api/http.ts`
- 当前默认值：`Authorization: Bearer stub-access-token`
- 如果后端切换正式登录态，可通过环境变量 `VITE_API_AUTHORIZATION` 覆盖
- 生产镜像构建时同样通过 `frontend/Dockerfile` 的 `VITE_API_AUTHORIZATION` 构建参数注入

### 4.3 字符串 ID 约定

- 后端使用长整型主键，真实返回值已超过 JavaScript 安全整数范围
- `frontend/src/api/http.ts` 对以下字段做了响应转换，统一按字符串使用：
  - `id`
  - `institutionId`
  - `campusId`
  - `termId`
  - `classId`
  - `studentId`
  - `teacherId`
  - `createdBy`
  - `updatedBy`
- 前端页面和接口入参均应继续使用字符串 ID，避免精度丢失

### 4.4 错误处理约定

- `frontend/src/api/request.ts` 统一按后端 `ApiResponse` 解包
- `success=false` 或 HTTP 异常会抛出 `ApiError`
- 页面表单当前约定：
  - 重复编码/名称、关系校验类错误直接显示在弹窗或表单区
  - 其他失败保留必要回退，不做前端错误路径暂存

### 4.5 当前页面承接范围

- `/students` 当前承接的是 `enrollment`，不是完整学员主数据维护
- `/classes` 当前承接的是 `class_student`，不是完整班级主数据维护
- `/schedule` 当前承接的是 `attendance`，不是完整排课引擎
- `/campus` 当前把校区、教室、学期、时间段收敛在一个入口内，目的是减少导航扩张，便于首版交付

## 5. 生产容器化说明

### 5.1 容器文件

- `frontend/Dockerfile`：多阶段构建，Node 负责 `pnpm build`，Nginx 负责托管 `dist`
- `docker/nginx/default.conf`：前端静态资源托管、`/api` 同源反向代理、SPA 路由回退、健康检查
- `docker/docker-compose.prod.yml`：前后端与 MySQL、Redis 的生产试运行编排

### 5.2 构建与运行口径

- 前端镜像构建上下文使用仓库根目录，`dockerfile` 指向 `frontend/Dockerfile`
- 默认暴露端口 `80`
- 健康检查地址：`/healthz`
- SPA 路由通过 `try_files $uri $uri/ /index.html` 回退，刷新子路由不会直接 404

### 5.3 当前生产前端约束

- 当前镜像仍默认携带 `stub-access-token`，仅适用于现阶段未接真实登录态的联调/试运行环境
- 若后续切换真实鉴权，优先替换 `VITE_API_AUTHORIZATION` 的构建参数，不应继续依赖 stub token
- 字符串 ID 转换发生在浏览器端 `axios transformResponse`，容器化不会改变这一行为
