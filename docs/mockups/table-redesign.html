2. 表头解剖：每一处改动的理由

✗ 竖边框 → ✓ 只留行线

满框网格把表切成一个个格子，视线每读一格都要重新定位。业界（Stripe、Linear、Notion 数据库视图）几乎都退成水平线。落地：主列表去掉 border 属性，保留 stripe？——不，见下一条。

✗ 斑马纹 → ✓ 行线 + 悬停

有行线时斑马是多余的第二套分隔信号，两者叠加会出摩尔纹，还会让人误以为「一行 = 一个色块组」 （合并单元格/展开行时更明显）。留行线 + 悬停高亮，够定位了。

✗ 表头强制居中 → ✓ 跟随列对齐

现在 styles/index.css 有一条把 th 及 th.is-left / .is-center / .is-right 一起写成 text-align: center 的全局规则（它排在 Element Plus 之后，所以把 EP 自己的对齐全覆盖了），而数据格是左/右对齐，标题跟内容错位。这条要删掉，改成「表头与它所标注的那一格同向」。

✗ 表头浅底 + 600 字重 → ✓ 无底 + 500 + 深一档底线

浅灰底 #f7f9fc 让表头看起来像「第一行数据」。去掉底色，靠 更深一档的底边线 --t-head-rule 与数据区分，字重 600→500、字号 13→12， 层级立刻轻下来。

✗ 数字居中/左混用 → ✓ 一律右对齐 + tabular-nums

「带班数 5 / 11 / 2」只有右对齐才能位数对齐比较。时间、金额、人数同理。 font-variant-numeric: tabular-nums 让每个数字同宽，纵向扫读不抖。 编码/手机号走等宽字体。

✗ 33px 行高 → ✓ 舒适 44 / 紧凑 34 两档

现在 padding: 5px 0 配 13px 字，中文笔画挤在一起。改成上下 11px（舒适）/ 6px（紧凑）， 并做成可切换档存本机，宽表（课次、完成度矩阵）默认紧凑，档案类默认舒适。

✗ 身份列只有一行姓名 → ✓ 主行 + meta 副行

班级、课次、学员这类列表真正要区分的是「名字 + 归属（校区/日期/编号）」。两行式把两个信息装进一列， 省掉一列宽度，也就省掉一次横向滚动。头像首字只用于教师/学员这类「以人为主」的表。

✗ 满屏蓝色 link 操作 → ✓ 低对比，悬停提亮

每行三个高饱和链接是「表格像表单」的主因。整行 hover 时才拉满对比度；点击目标尺寸不变（44px 行高足够），键盘聚焦时也要常显，不能只靠 hover。超过两个动作收进「更多」。

✗ 状态是彩色实心 tag → ✓ 圆点 + 文字，异常才给色块

这条我们已经做了（.el-tag--success 那一段），新方案沿用：常规态「圆点+文字」， warning/danger 才用软色胶囊，保证异常在一列灰字里跳出来。

3. 宽表：固定身份列 + 滚动提示 + 紧凑档

排课课次，列多、要横向滚

这类表的重点不在好看，在横向滚动时不迷路：身份列固定 + 一道渐变阴影告诉人「右边还有列」+ 表头吸顶。日期与星期合并成两行式，省两列；状态与变动类型并排，省一列。

5. 如果照这个方向做，要动的地方

  1. core 全局样式一处：packages/core/src/styles/index.css 的表格段——删掉「表头统一居中」那条；表头去底色、字重 500、底线加深；行线替换竖线；行高两档。 这一步覆盖所有手写表和 ConfigurableList。
  2. 各视图模板去掉两个属性：<el-table border stripe> 里的 border 与 stripe（全站 21 个文件带 stripe，其中 ConfigurableList 一处改动即覆盖所有配置化列表；弹窗内的次要表格可保留斑马纹，因为它没有横向滚动）， 并把数字/时间列补 align="right"。
  3. AGENTS.md 那条口径要同步改：现在写的是「主列表一律 border stripe row-key highlight-current-row」，改后只剩 row-key + highlight-current-row， 并新增「表头跟随列对齐」「数字右对齐 + tabular-nums」两条判据。
  4. 要新增的小能力（可选，分批）：密度切换（存本机）、列设置里勾可见/固定、 表头吸顶（EP 的 :height 已具备）、固定列滚动渐变提示、骨架行。 这些不删也能活，优先级低于 1~3。
  5. 不建议照搬的：卡片式行、行间隔大圆角、给每列加彩色底、把整表换成「多维表格」编辑器 ——那是协作工具（飞书/Notion）的形态，我们是高频扫读的后台，密度和确定性优先。

6. 行业参考：分别去看哪一处

不是抄样式，是抄它们对同一问题的答案

下面每一个都标了「看什么」，比对着看比我们自己的表快。前四个是产品，后三个是规范文档。

Stripe Dashboard · Customers / Payouts

dashboard.stripe.com —— 收钱类后台的天花板。看三件事： 金额全部右对齐且等宽数字、表头跟数据同向、页面底部一条「本页合计」。 它的行也没有斑马纹，只有极浅的行线 + hover。

Linear · Issues 列表

linear.app —— 看操作按钮什么时候出现：整行 hover 才显形， 平时只剩标题和状态，所以一屏 40 行也不吵。也看它怎么把「指派人 + 状态 + 优先级」压进一列。

GitHub · Issues / Actions

任意仓库的 Issue 列表 —— 看状态用图标+文字而不是色块，以及行高恒定、 只有底边线的极简分隔。这是「降噪之后还认得出哪一行」的最省钱解法。

Ant Design Pro · ProTable

procomponents.ant.design/components/table —— 中文后台里 筛选行 / 按钮行 / 表格 三段式最成熟的实现，也给了「密度（紧凑/默认/宽松）」三档和 列设置面板的标准交互。我们的筛选行顺序已经跟它一致，缺的是密度与列设置。

shadcn/ui · Data Table

ui.shadcn.com/docs/components/base/data-table —— 看它把排序、列显隐、分页、行选择四件事都放在哪，是一套可以直接对照的清单。

Semi Design · Table

semi.design/zh-CN/show/table —— 国产设计系统里对 虚拟滚动、固定列、分组表头、合计行说明最清楚的一份，跟我们「课次完成度矩阵」最相关。

研究：企业级表格 UX 模式汇总

pencilandpaper.io/articles/ux-pattern-analysis-enterprise-data-tables 与 valiotti.com/designing-data-tables-readable/ —— 结论就是本页第 2 节那九条：先减分隔线、再管对齐、最后才谈配色。
