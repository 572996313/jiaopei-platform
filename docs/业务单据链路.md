## 1. 先分清四层关系

| 层 | 回答的问题 | 页面怎么处理 |
| --- | --- | --- |
| 全表节点 | 库里的表是不是都能找到 | 模块登记过的单据优先；没有登记归属的表按数据字典补成「仅表」节点 |
| 引用关系 | 这张单据挂在哪些主数据上（机构、校区、班级、学期、学员） | 数据库外键自动补成「引用」关系，按节点对聚合，页面标「外键」 |
| 生成关系 | 这张单据是根据哪些单据做出来的 | **本文的重点**，由各模块在 `DocumentLineageContributor` 里显式声明 |
| 运行记录 | 某一次点击实际读了哪些表、写了哪些表 | 不在本文范围，看「接口链路」页 |

外键能自动补引用，但补不出生成关系：收费台账引用了班级、学期、学员，
但「台账是由名册生成的」「发生额是由考勤重算的」这些关系外键里根本没有，
它们写在 `FeeLedgerServiceImpl` / `FeeAttendanceServiceImpl` / `FeeBillingEngine` 里，必须显式登记。

## 2. 全景图

```text
【主数据 / 引用】                 【教务执行】                    【收费单据】

机构 / 校区 / 学期 / 班级 ─┐
学员 ──────────────────────┼─引用─> 收费台账（头）
                           │              │
收费项目 ──────────────────┼─引用─> 应收台账明细 <─取价─ 收费价目
                           │              │
                           │              ├─展开──────> 逐月发生额（按明细 × 账期）
                           │              │                    ▲
                           │              │                    │重算
周期排课计划 ──展开──> 课次 ──点名──> 考勤 ──按月汇总──> 月度出勤 ─┘
自动排课批次 ──生成──> 课次
                           │
                           └─登记收款──> 收款流水（引用台账明细，不回写金额）
```

一句话读法：

> 名册建台账 → 收费项展开明细 → 考勤汇总成月度出勤 → 出勤和明细重算出逐月发生额 → 收款流水挂到明细上做核销。

这张图只画业务主链。页面还会自动补上所有未登记的表与数据库外键引用（系统表也会出现），
所以页面节点数会明显多于这张图；勾「只看有上下游」可以收敛到真正连着关系的节点。

## 4. 逐条链路

### 4.1 名册 → 收费台账 → 台账明细

- **关系**：生成（批量）
- **入口**：收费台账页「按名册建账」→ `POST /api/education/fee-ledgers/generate`
- **口径**：取该班级 `status=active` 的名册学员，为每个学员建一份台账；已有台账的跳过。
  每建一份台账，立即按当前启用的收费项目展开明细，并按价目表取价，然后生成逐月发生额。
- **唯一性**：`uk_jp_fee_ledger_student (institution_id, term_id, class_id, student_id, deleted)`，
  并发重复建账由唯一键兜底，捕获后按「已存在」跳过。
- **代码**：`FeeLedgerServiceImpl#generate` / `applyItems` / `rebuildMonthly`
- **状态**：已确认

### 4.2 收费项目、收费价目 → 台账明细

- **关系**：引用 + 取价
- **入口**：新建/编辑台账；「重新取价并重算」→ `POST /api/education/fee-ledgers/{id}/resolve-prices`
- **口径**：
  - 明细的收费项目来自 `jp_fee_item`，台账保存时按整表覆盖；
  - 月标准/日标准由 `FeePriceResolver` 取价，优先级 **学员 8 > 班级 4 > 校区 2 > 学期 1**，
    每个维度 `0`/`NULL` 表示不限；月标准和日标准各自独立回落；
  - 手工填了标准时来源记 `MANUAL`，否则记 `PRICE` / `STUDENT` 并保留 `price_id`。
- **代码**：`FeeLedgerServiceImpl#upsertItem`、`FeePriceResolver`
- **状态**：已确认

### 4.3 考勤 → 月度出勤

- **关系**：按月汇总
- **入口**：台账页「从考勤汇总」→ `POST /api/education/fee-attendance/sync`
- **口径**：按班级 + 账期汇总 `jp_attendance`，只算 `present` / `late`，用
  `COUNT(DISTINCT attendance_date)`（一天多节课只算一天）。写入 `jp_fee_attendance_month.autoDays`；
  没有手工覆盖时，`attendanceDays` 同步成自动值。汇总完立即触发一次逐月发生额重算。
- **保护**：`manualOverride=true` 的月份保留人工值，只更新 `autoDays`。
- **代码**：`FeeAttendanceServiceImpl#sync`、`FeeAttendanceMonthMapper#sumDaysByClassAndMonth`
- **状态**：已确认

### 4.4 台账明细 + 月度出勤 → 逐月发生额

- **关系**：生成 / 重算
- **入口**：「重算发生额」→ `POST /api/education/fee-monthly/recalculate`
  （传台账只重算一份；否则同时传学期与班级批量重算）
- **口径**：
  - 按月项目：`月标准 × 月份系数`，当月无出勤默认 0；
  - 按天项目：`日标准 × 出勤天数`；
  - `monthFactor` 为空时按学期首月规则给默认值（首月从 2 号起算的半月记 0.50，否则 1.00）；
  - `autoAmount` 永远记录自动算出的值；`manualOverride=true` 时 `occurrenceAmount` 保留人工值。
- **代码**：`FeeLedgerServiceImpl#rebuildMonthly`、`FeeBillingEngine#monthlyOccurrence` / `dailyOccurrence` / `defaultFactor`
- **状态**：已确认

### 4.5 收款流水 → 台账明细（核销）

- **关系**：核销（引用，不回写）
- **入口**：「登记收款」→ `POST /api/education/fee-payments`
- **口径**：收款流水记录 `ledger_id`、`ledger_item_id`、`billing_month`、金额与收款日期；
  **不修改台账明细和逐月发生额**。实收、未收费、结余都是查询时由流水现算，避免两本账。
  金额允许负数，用于冲正；删除收款是逻辑删除，实收合计立即变化。
- **代码**：`FeePaymentServiceImpl#createPayment`、`FeeLedgerServiceImpl#buildDetail`
- **状态**：已确认

### 4.6 课次 → 考勤；排课计划 / 自动批次 → 课次

- **关系**：执行记录 / 展开 / 生成
- **口径**：`schedule_lesson` 是排课结果；`jp_attendance` 按「学员 × 课次」记录出勤。
  课次来源看两个字段：`plan_id` 非空 = 周期计划展开，`auto_batch_id` 非空 = 自动补排，都为空 = 手工加排。
- **代码**：`SchedulePlanExpander`、`ScheduleAutoBatchServiceImpl`、`AttendanceServiceImpl`
- **状态**：已确认

### 4.7 台账明细 → 台账明细（结转，预留未启用）

- **关系**：结转
- **口径**：`jp_fee_ledger_item.carry_from_item_id` / `carry_at` 是 V99 预留的结转凭证字段，
  当前代码里只有实体字段，**没有任何服务写入或读取**。不要把它当成已上线的业务关系；
  需要「上期结余自动结转」时再单独设计。
- **状态**：未落地（待确认是否需要）

## 6. 待业务确认的问题

这些问题代码里没有答案，必须业务拍板；确认结果会直接变成后续「业务链路」页里的节点和边：

1. **台账粒度**：现在是一学员 × 一班级 × 一学期一份。是否存在「跨班合并收费」「一个学员一学期只想要一份总台账」的场景？
2. **转班/插班**：台账的班级建账后不可改；月度出勤按台账所属班级汇总。学员中途转班时，历史出勤和未来出勤应该怎么归属？
3. **退费/冲正**：现在用「负数收款」冲正，没有独立退费单。财务是否需要一个可打印、可审批的退费单据？
4. **结转**：`carry_from_item_id` 预留未用。上期结余现在是手工填在 `opening_balance`，是否要改成系统自动结转？
5. **收款与账期的关系**：收款流水可以挂 `billing_month`，但当前核销是「整条明细的实收合计」，不按月份抵扣。财务口径是按月核销还是按明细核销？
6. **班级变动通知**：`jp_class_change_notice` 目前是独立通知单据，不进入收费链。它是否应该影响台账（例如停课退费）？
