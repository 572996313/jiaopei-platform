# 小程序企业端（收费台账 + 学员班级）设计与功能清单

> 定位：给**已有管理后台账号**的机构运营/财务人员用的移动端工作台。
> 不新建账号体系、不走小程序自助注册，直接用管理后台的账号密码登录，因此
> `portal = admin`，权限码与 PC 完全同源；学生/家长端继续走微信一键登录。

---

## 一、为什么不是「新增一个企业注册身份」

- 小程序自助注册链路（`WechatAuthServiceImpl` + 邀请码角色白名单）目前只放行
  `MINIAPP_STUDENT` / `MINIAPP_PARENT`。如果把企业角色塞进这条链路，等于让拿到邀请码的人
  自助获得 `education:fee:write`，属于提权，不能这么做。
- 企业用户本来就是平台已有账号（机构运营 110、平台管理员 1，或现场自建的财务角色）。
  复用 `POST /api/auth/login` 账号密码登录即可，令牌与 PC 同构，后端零改造。

## 二、登录与端判定

| 项 | 口径 |
| --- | --- |
| 登录入口 | 登录页新增「企业用户登录」→ 账号密码页 |
| 登录接口 | `POST /api/auth/login`（公开接口，已有） |
| 端判定 | `/api/auth/me` 返回 `portal`；`admin` = 企业端，`student`/`parent` = 学生/家长端 |
| 会话恢复 | 微信端仍走 `wx.login` 静默重登；**账号密码端不静默重登**，401 回登录页（否则会把企业会话静默换成该微信的学生/家长账号） |
| 模块可见性 | 首页与企业工作台按 `portal` 分支；企业端不调用 `/api/miniapp/**` 任何接口 |

### 底部导航：看与做分开

| Tab | 企业账号 | 学生 / 家长 |
| --- | --- | --- |
| 首页 | 只读收费概览（总数/在收/已结清）+ 最近在收台账 | 今日课程 |
| 工作台 | 一级入口：收费台账（含新增/按班建账/收款）、收费项目、价目、学员档案、班级与入班 | 课程表、消息、同班名单、档案/绑定 |
| 我的 | 身份、所属机构、退出 | 学员管理、档案、退出/注销 |

企业账号登录成功后直接进入**工作台**；首页不再放任何新增/收款/维护按钮，
写操作集中在工作台下一级页面。工作台自身不重复「新增台账 / 按班建账 / 新增学员 /
新增班级」这类列表页已有的按钮，同一件事只保留一个入口。

现场常常没人维护；现在同一批管理后台账号可以在小程序里完成，不必回 PC。

## 四、本期不做（下一批）

1. **导出矩阵 / 一维明细**：微信端需要 `uni.downloadFile` + `openDocument`，是独立风险；
   PC 端导出继续保留。需要时按「刷新后打开临时文件」单独做。
2. **学期起止日期维护**：属于 `organization:write`，不在收费域；建账时若后端报
   「学期未维护起止日期」，页面原样提示并注明「请到管理后台补齐学期日期」。
3. **课次点名**：出勤同步读取的是现有考勤数据，点名仍在 PC 或既有小程序端完成。
4. **学员批量导入、教师档案、课程/班型主数据维护**：仍在 PC 端维护；小程序只消费这些主数据。

## 五、权限与数据范围

- 页面与接口权限沿用 PC：读 `education:read`，台账/收款/出勤/逐月写 `education:fee:write`，
  收费项目与价目写 `education:fee:config:write`；学员与家长联系人写 `education:profile:write`，
  班级与入班写 `education:class:write`；基础资料选择额外需要 `organization:read`。
- 机构与校区范围完全由后端 `InstitutionScopeGuard` / `CampusScopeGuard` 兜底。
  收费域接口不传 `institutionId`，默认取登录账号所属机构；学员与班级的**新增**接口要求
  显式传 `institutionId`（后端 `@NotNull`），小程序统一取 `/auth/me` 的 `institutionId`
  （小号账号为空的场景回落到 `orgId`）。
- 金额一律由服务端现算，小程序只展示，不做第二套公式。

## 六、必须守住的语义

1. **台账明细是整表覆盖**：`PUT /fee-ledgers/{id}` 的 `items` 是整份明细，未列出的项目在
   「无收款且无手工覆盖」时会被删除。小程序编辑页按整表提交，并显式提示这一点。
2. **月标准/日标准留空 = 按价目表重新取价；显式填 0 = 免费**，表单要区分空串与 0。
3. **逐月覆盖按 `ledgerItemId + billingMonth`**，**出勤覆盖按 `ledgerId + billingMonth`**，两者键不同。
4. **班级编辑是整表单覆盖**：`PUT /education/classes/{id}` 必须带全量字段；`weeklyLessonsInput`
   留空会清掉课时目标，`teacherId` 传 `null` 会撤销主讲教师。小程序编辑页始终回填后再提交。
5. **入班没有更新端点**：新增走 `POST`，退班/移出只能 `DELETE`（物理删除关系），需要保留
   离班历史的仍在 PC 处理。
6. 所有雪花 ID 按字符串透传，禁止 `Number()` / `parseInt()`；小号机构的主数据 id 运行期
   可能是数字，比较与回显统一 `String()` 后再用。
