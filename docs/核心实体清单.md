# 核心实体清单

## 目标

反映当前实际落地的表清单（按 Maven 模块归属分组），作为"现行 schema 事实"的速查；schema 变更一律走 Flyway，最终以 `backend/app/src/main/resources/db/migration/` 迁移脚本为准。

历史"首版建模约束"类文档已移至 `docs/archive/`，其表名（如 `sys_user`、`jp_org`、`jp_lesson`）多数未采用，勿引用。

## 底座 cornerstone-core

### 认证授权（auth 包）

| 表 | 说明 |
| --- | --- |
| `sys_user_account` | 登录账号（用户名、密码哈希、强制改密、上次登录；默认校区已移出底座，见 `jp_user_campus_pref`） |
| `sys_role` | 角色（含接口权限码列表 `permission_codes`） |
| `sys_user_role_rel` | 用户-角色关系 |
| `sys_auth_provider` | 第三方登录渠道配置（一渠道一行：端点、密钥、字段映射；协议实现在代码里，见 `第三方登录接入方案.md`） |
| `sys_user_identity` | 第三方身份绑定（`provider_code + app_type + open_id + user_id` 唯一，同一外部身份可绑多个账号；V121 迁入原 `jp_wechat_binding` 后删旧表） |

> 阶段五-0b 起底座表统一 `sys_` 前缀（V40 `RENAME TABLE`）；索引/外键/检查约束名（`uk_jp_*`、`fk_jp_*`、`chk_jp_*`）保持历史命名不随表改名。
> 曾有的 `jp_user_token`（登录令牌）在 V14 就随 Redis 会话改造 DROP，只留下 `UserTokenEntity`/`UserTokenMapper` 死代码，阶段五-0d 清理。

## 业务模块 module-education（教务业务）

### 人员

| 表 | 说明 |
| --- | --- |
| `jp_teacher` | 教师（`max_weekly_lessons` / `max_daily_lessons` = 周/日课时上限，超出只提示不拦，NULL=不限） |
| `jp_student` | 学员 |
| `jp_student_parent` | 学员家长（关系、主联系人、紧急联系人） |
| `jp_user_student_rel` | 账号-学员关联（小程序家长绑定） |

### 课程与班级

| 表 | 说明 |
| --- | --- |
| `jp_course_category` / `jp_course` | 课程分类 / 课程 |
| `jp_class_type` | 班型（最小/最大人数、授课方式） |
| `jp_class` | 班级（`term_id` 可为 NULL，学期是可选维度；`weekly_lessons` = 每周应上节数，自动排课目标与课时完成度分母，NULL=未设定；`weekly_lessons_mode` + `weekly_lessons_input` = 该值的录入口径与原始填写值（monthly 时存每月节数，换算只在保存时做一次），只服务表单回显、不参与任何算账；`total_lessons` = 整班总课时，只喂课时完成度页的「已上课 N/M」进度，**不进完成度分母**，NULL=未设定） |
| `jp_class_teacher` | 班级-教师（主讲/助教/班主任） |
| `jp_class_student` | 班级-学员（入班/退班，不涉及学期；V109 起即报名记录，`channel` = 来源渠道） |
| `jp_class_opening_rule` | 开班规则 |
| `jp_class_change_notice` | 班级变动通知 |

### 排课与执行

| 表 | 说明 |
| --- | --- |
| `jp_schedule_plan` | 周期排课计划（`slots_json` 每周节次模式 + `week_frequency` 单双周 + `skip_dates_json` 停课日，展开生成课次） |
| `jp_schedule_auto_batch` | 自动排课批次（按缺口补排的执行记录与整批撤销依据：窗口、生效策略、生成/未补上数与原因、`completed`/`rolled_back`） |
| `jp_schedule_rule` | 禁排/必排规则（`target_type` = class/teacher/classroom，作用域按「星期×节次」格子） |
| `jp_school_calendar_day` | 校区日历停排日（法定假/检修等当天不可排课；`campus_id=0` 表示全校区；只提示不拦） |
| `schedule_lesson` | 课次/排课明细（`term_id` NOT NULL，唯一强制学期的实体；V72 的班级/教室占用生成列唯一键兜并发写入；`plan_id` 为空=手工/补排产物，`auto_batch_id` 非空=自动排课批次生成） |
| `schedule_teacher_rel` | 课次-授课教师（教师占用跨两表建不了唯一键，写入前按教师 ID 升序取 `FOR UPDATE` 行锁） |
| `jp_attendance` | 考勤（学员-课次出勤状态） |

```
机构 sys_institution（租户）
 ├─ 校区 jp_campus
 │   └─ 教室 jp_classroom
 ├─ 学期 jp_term
 ├─ 时间段 jp_time_slot ←（模板生成）jp_time_slot_template

 ├─ 教师 jp_teacher
 ├─ 课程分类 jp_course_category ─ 课程 jp_course
 ├─ 班型 jp_class_type
 ├─ 开班规则 jp_class_opening_rule
 ├─ 校区日历 jp_school_calendar_day（停排日，`campus_id=0` 为全校区）
 ├─ 班级 jp_class（校区 + 学期 + 课程 + 班型）
 │   ├─ 班级学员 jp_class_student（V109 起即报名记录，带来源渠道）
 │   ├─ 班级教师 jp_class_teacher（主讲/助教/班主任）
 │   ├─ 变动通知 jp_class_change_notice
 │   ├─ 周期排课计划 jp_schedule_plan
 │   ├─ 排课规则 jp_schedule_rule（对象=班级/教师/教室）
 │   └─ 课次 schedule_lesson（班级 + 时段 + 教室 + 学期；来源二选一：`plan_id`←周期计划展开 / `auto_batch_id`←自动补排，都为空即手工加排）
 │       ├─ 课次教师 schedule_teacher_rel
 │       └─ 考勤 jp_attendance（学员 × 课次）
 ├─ 自动排课批次 jp_schedule_auto_batch（校区 + 学期 ─→ 课次 schedule_lesson.auto_batch_id）
 └─ 账号 sys_user_account ─ 角色 sys_role ─ 菜单 sys_menu
                        ├ sys_role_menu
                        └ 默认校区偏好 jp_user_campus_pref ─→ 校区 jp_campus（业务模块维护）
```

## 命名与通用字段

- 前缀规律（阶段五-0b 起）：`sys_` = 底座表（认证授权 + 系统配置 + 租户）、`jp_` = 教培业务表、`oper_log` 审计库表；例外：`schedule_lesson`、`schedule_teacher_rel` 未带 `jp_` 前缀（存量，不回改）。索引/外键/检查约束名（`uk_jp_*`、`fk_jp_*`、`chk_jp_*`）不随 V40 的表改名，属历史遗留。
- `flyway_schema_history` 为框架表，不算业务实体。
- 实体统一继承 `BaseEntity`：雪花 `Long` id、审计字段（`created_at/by`、`updated_at/by`）、`deleted` 逻辑删除（唯一索引必须包含 `deleted` 列）。
