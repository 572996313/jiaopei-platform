# 主讲与主联系人切换规则

> 状态：**已归档（历史过程方案，不再维护，2026-09-20）**。规则已落入班级教师与学员家长的维护逻辑（`module-education`），如与现行代码行为不一致，以代码为准。

## 1. 目标

这套规则解决两个现实问题：

1. 老师或联系人发生变动时，系统不能只报错，必须能自动收口。
2. 成班后前面信息变了，后面的排课、点名、执行要能看到影响提示。

## 2. 班级主讲教师规则

### 2.1 设新主讲

- 当某条班级教师关系被设置为主讲时，系统自动将同班其他主讲关系降为非主讲。
- `jp_class.teacher_id` 同步写成新的主讲教师。
- 生成一条 `primary_teacher_changed` 提示，提示教务确认后续排课和执行安排。

### 2.2 删除主讲

- 删除当前主讲后，系统优先从同班仍有效的在班教师里自动补位一个新的主讲。
- 自动补位顺序：
  1. `status = active`
  2. `left_at` 为空或未早于今天
  3. 按 `joined_at`、`id` 顺序取最前一条
- 若补位成功：
  - 自动把该教师设为主讲
  - 同步 `jp_class.teacher_id`
  - 生成 `primary_teacher_changed` 提示
- 若没有可补位教师：
  - 清空 `jp_class.teacher_id`
  - 生成 `missing_primary_teacher` 提示

### 2.3 非主讲更新

- 如果原主讲被改成非主讲，而班级内没有其他主讲，系统同样按补位规则自动补主。
- 不允许长期存在“班级有人，但没有主讲且系统无提示”的状态。

## 3. 学员主联系人规则

### 3.1 设新主联系人

- 当某条家长联系人被设置为主联系人时，系统自动将同学员其他主联系人降为非主联系人。
- 学员平铺字段 `guardian_name / guardian_phone` 同步写为新的主联系人信息。

### 3.2 删除主联系人

- 删除当前主联系人后，系统优先从同学员仍有效的联系人里自动补位。
- 自动补位顺序：
  1. `status = active`
  2. 按 `id` 顺序取最前一条
- 若补位成功：
  - 自动把该联系人设为主联系人
  - 同步学员 `guardian_name / guardian_phone`
- 若没有可补位联系人：
  - 清空学员 `guardian_name / guardian_phone`

## 4. 首批必须提示的班级变动

首批先收口到最关键的几类：

1. `primary_teacher_changed`
说明：班级主讲发生切换。
建议动作：检查后续排课、待点名课次、代课安排。

2. `missing_primary_teacher`
说明：班级已无可用主讲。
建议动作：尽快指定主讲，否则后续排课和执行会失真。

## 5. 首批明确不做

- 不做复杂审批流。
- 不做历史版本比对页。
- 不做自动改写未来所有课次任课老师。
- 不做通知消息推送。
- 不做规则引擎式多条件冲突处理。

## 6. 验收标准

1. 同班设置新的主讲时，旧主讲自动降级，不再报“已有主讲”的阻断错误。
2. 删除主讲后，如果班级还有有效教师，系统自动补主；没有则清空主讲并生成提示。
3. 同学员设置新的主联系人时，旧主联系人自动降级。
4. 删除主联系人后，如果还有有效联系人，系统自动补主；没有则清空学员平铺联系人字段。
5. 教务可以通过 `class_change_notice` 查询到主讲切换和缺失提示。
